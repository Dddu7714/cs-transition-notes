# OTTO 项目 

## 1. 推荐系统链路

**1. 推荐系统一般分为哪几个阶段？**
常见链路是**召回、粗排、精排、重排**。召回从海量商品中快速选出几百到几千个候选，粗排做初步筛选，精排用复杂模型精细打分，重排再结合多样性、去重、业务规则等调整最终结果。

**2. 召回、粗排、精排、重排分别做什么？**
召回强调速度和覆盖率，目标是不要漏掉用户可能感兴趣的商品。粗排在候选较多时用轻量模型过滤；精排用更丰富特征和复杂模型预测点击、转化或价值；重排主要处理体验和业务约束，比如多样性、频控和运营策略。

**3. 召回阶段为什么要快？**
因为召回面对的是全量商品库，规模可能是百万级甚至亿级，不可能对每个商品都用复杂模型打分。所以召回通常用共现、向量检索、规则、多路召回等高效方法。

**4. 精排阶段为什么可以用更复杂的模型？**

因为经过召回和粗排后，候选数量已经大幅减少，通常只剩几百个以内。此时可以引入更多用户、商品、上下文和交叉特征，用深度模型或 GBDT 类模型做更精细排序。

**5. 召回和排序的目标有什么区别？**

召回更关注覆盖率，希望把可能相关的商品尽量找回来；排序更关注顺序，希望把最可能点击、加购、购买的商品排到前面。召回漏掉的商品，后面的排序模型无法补救。

**6. 推荐系统为什么需要多路召回？**

单一路召回只能覆盖某一类兴趣，比如热门、相似商品、用户长期兴趣或短期行为。多路召回可以从不同角度覆盖候选，提高整体召回率和鲁棒性。

**7. 多路召回结果如何融合？**

常见做法包括按召回源配额截断、按规则加权、归一化后融合分数，或者将召回源、召回 rank 作为排序特征交给后续模型学习。OTTO 项目里 candidate_rank 就可以看作召回阶段的排序信号。

**8. 冷启动问题有哪些？**

主要包括新用户冷启动、新商品冷启动和新场景冷启动。<u>新用户缺少历史行为，新商品缺少交互数据，新场景则可能数据分布和历史场景不同</u>。

**9. 用户冷启动怎么解决？**

可以利用注册信息、设备、来源渠道、地理位置、实时短行为、热门内容和探索机制。业务上也可以先用规则或热门推荐，随着用户行为积累逐步切换到个性化模型。

**10. 物品冷启动怎么解决？**

可以利用商品类目、标题、图片、价格、品牌等内容特征，也可以通过曝光探索、相似商品迁移和内容 embedding 召回。单纯依赖共现的 ItemCF 对新商品不友好。



## 2. CTR / CVR / LTV / LT

**1. CTR 是什么？**

**CTR 是点击率**，通常等于点击次数除以曝光次数，衡量用户看到内容后是否点击。它反映短期兴趣，但不一定代表最终商业价值。

**2. CVR 是什么？**

**CVR 是转化率**，通常表示用户点击或曝光后产生购买、注册、付费等目标行为的概率。相比 CTR，它更接近业务收益。
。

**4. LTV 是什么？**

**LTV 是用户生命周期价值**，表示一个用户在未来一段时间内能为平台带来的总价值，例如收入、GMV、利润或活跃贡献。它比单次点击、单次转化更强调长期收益。

**5. LT 是什么？**

**LT 可以理解为用户生命周期**或留存周期，关注用户能持续活跃多久、多久后流失。它常和留存、流失预测、用户活跃周期建模有关。

**6. 留存率是什么？**

留存率表示某批用户在一段时间后仍然活跃的比例，比如次日留存、7 日留存、30 日留存。它是衡量产品粘性和用户长期价值的重要指标。

**7. 流失预测是什么？**

流失预测是判断用户未来是否会不再活跃或不再消费。它通常基于用户最近活跃频率、行为变化、消费行为、登录间隔等特征建模。

**8. 为什么不能只优化 CTR？**

CTR 只反映点击，不一定带来购买、留存或长期价值。过度优化 CTR 可能导致标题党、低质内容或短期刺激，反而伤害用户体验和长期留存。

**9. 为什么 LTV 预估比 CTR 更难？**

CTR 是短期行为，反馈快、样本多；LTV 是长期目标，反馈延迟、噪声大、受时间窗口和用户生命周期影响更明显。LTV 还可能存在数据截断和目标稀疏问题。

**10. LTV 预估可以看成分类还是回归？**

两种都可以。预测未来收入或价值金额时是回归任务；预测是否成为高价值用户、是否付费或是否留存时可以转成分类任务。

**11. LT 预估可以看成什么任务？**

可以看成留存分类、流失预测，也可以看成生存分析或时间到事件预测问题。如果目标是预测还能活跃多久，也可以建模为回归或序列预测。

**12. 长周期目标延迟反馈怎么办？**

可以使用短期代理目标、多任务学习、分阶段目标、延迟反馈建模和滑动时间窗口。比如用点击、加购、短期留存辅助长期 LTV 学习。

**13. 如果 CTR 高但留存下降，你怎么分析？**

说明模型可能过度优化短期兴趣，推荐了吸引点击但长期体验不好的内容。需要进一步看 CVR、停留时长、复访率、负反馈、长期留存等指标，必要时调整多目标权重。



## 3. 机器学习基础

**1. 分类和回归有什么区别？**

分类预测离散类别，比如是否点击、是否流失；回归预测连续数值，比如未来消费金额、LTV 数值。二者的标签、损失函数和评估指标通常不同。

**2. 过拟合和欠拟合是什么？**

过拟合是模型在训练集表现很好，但在验证集或测试集表现差，说明记住了噪声。欠拟合是训练集和验证集表现都不好，说明模型表达能力不足或特征不够。

**3. 如何解决过拟合？**

常见方法包括<u>增加数据、做正则化、降低模型复杂度、早停、特征筛选、Dropout、交叉验证和数据增强</u>。对于树模型，也可以限制深度、增加叶子最小样本数、使用 subsample 和 colsample。

**4. L1 和 L2 正则有什么区别？**

L1 正则倾向于让部分参数变为 0，具有**特征选择**效果；L2 正则倾向于让参数整体变小，使模型更平滑。两者都可以缓解过拟合。

**5. 偏差和方差是什么？**

偏差反映<u>模型假设与真实规律之间的差距</u>，偏差高容易欠拟合；方差反映<u>模型对训练数据扰动的敏感程度</u>，方差高容易过拟合。    
模型调优本质上是在偏差和方差之间平衡。

**6. 交叉验证是什么？**

交叉验证是把训练数据分成多折，轮流用其中一折做验证，其余做训练，从而更稳定地估计模型泛化能力。推荐排序里如果样本有 group，需要用 GroupKFold 避免同一 group 泄漏。

**7. 逻辑回归原理是什么？**

逻辑回归是线性模型通过 sigmoid 函数把线性组合映射到 0 到 1 之间，用于估计二分类概率。它简单、可解释，但表达非线性和特征交互的能力有限。

**8. 决策树怎么划分节点？**

决策树每次选择一个特征和切分点，使划分后的样本更加纯。分类树常用信息增益、信息增益率或基尼指数，回归树常用平方误差下降。

**9. 随机森林为什么能降低方差？**

随机森林通过 bootstrap 抽样训练多棵树，并在特征上引入随机性，最后做投票或平均。多个弱相关模型集成后可以降低方差，提升泛化能力。

**10. GBDT 和随机森林有什么区别？**

随机森林是 bagging 思想，多棵树并行训练，主要降低方差；GBDT 是 boosting 思想，树按顺序训练，每棵树拟合前面模型的残差或负梯度，主要降低偏差。

**11. SVM 的最大间隔思想是什么？**

SVM 希望找到一个分类超平面，使两类样本之间的间隔最大。间隔越大，模型对扰动越不敏感，泛化能力通常更好。

**12. 交叉熵损失是什么？**

交叉熵衡量真实分布和预测分布之间的差异。分类任务中，预测概率越接近真实标签，交叉熵越小。

**13. MSE 损失是什么？**

MSE 是均方误差，衡量预测值和真实值之间差的平方平均。它常用于回归任务，但对异常值比较敏感。

**14. 为什么分类常用交叉熵？**

分类模型通常输出类别概率，交叉熵直接优化真实类别的预测概率。相比 MSE，交叉熵在概率分类中<u>梯度性质</u>更合适，训练更稳定。



## 4. XGBoost / GBDT

**1. GBDT 的基本思想是什么？**

GBDT 是梯度提升决策树，每一轮新增一棵树去拟合当前模型的负梯度，也可以理解为不断修正前面模型的错误。最终多个弱学习器加和形成强模型。

**2. XGBoost 相比传统 GBDT 有哪些改进？**

XGBoost 在目标函数中加入二阶泰勒展开和正则项，支持列采样、缺失值默认方向、并行分裂查找、稀疏感知和高效工程实现。因此它通常训练更快、效果更稳，也更能控制过拟合。

**3. XGBoost 为什么适合结构化特征？**

树模型天然擅长处理非线性、特征交互、不同量纲特征和缺失值。OTTO 项目中大量特征是统计特征和交叉特征，正适合 XGBoost 这类树模型。

**4. XGBoost 如何防止过拟合？**

可以通过树深度、叶子最小权重、正则项、学习率、子采样、列采样和 early stopping 控制过拟合。调参时通常先控制模型复杂度，再调整学习率和迭代轮数。

**5. learning_rate 的作用是什么？**

learning_rate 控制每棵树对最终模型的贡献，也叫 shrinkage。较小学习率通常更稳定，但需要更多树；过大可能收敛快但泛化差。

**6. max_depth 太大会怎样？**

max_depth 越大，单棵树表达能力越强，能捕捉更复杂的特征组合，但也更容易过拟合，训练和预测成本也更高。

**7. subsample 和 colsample_bytree 有什么作用？**

subsample 是每棵树训练时采样部分样本，colsample_bytree 是采样部分特征。它们都能引入随机性，降低过拟合，并加快训练。

**8. 为什么推荐排序常用 GBDT/XGBoost/LightGBM？**

推荐排序常有大量结构化特征，比如用户统计、商品统计、交叉统计和上下文特征。GBDT 类模型对这类特征很强，调参成本相对深度模型低，离线效果稳定。

**9. 为什么不用逻辑回归？**

逻辑回归是线性模型，难以自动学习复杂非线性和高阶特征交互。OTTO 项目里 session、商品、行为统计之间存在复杂关系，用 XGBoost 更容易捕捉。

**10. 为什么不用深度模型？**

深度模型适合有丰富 embedding、文本、图像或长序列数据的场景，但训练成本高、调参复杂。OTTO 项目主要是结构化统计特征，XGBoost 更稳定，也更适合快速做强 baseline。

**11. XGBoost 输出的 score 是什么？**

在排序任务中，score 不是严格概率，而是用于同一个 group 内比较排序的分数。分数越高，模型认为该候选商品越应该排在前面。

**12. 特征重要性怎么看？**

可以看 split 次数、gain 或 cover，其中 gain 更常用于衡量特征对目标函数下降的贡献。但特征重要性只能辅助分析，不能完全等同于因果解释。

**13. XGBoost 和神经网络有什么优缺点？**

XGBoost 对表格特征强、训练稳定、可解释性相对好；神经网络适合高维稀疏特征、序列、文本和多模态，但需要更多数据和算力。真实业务中两者常结合使用。



## 5. Learning to Rank 排序学习

**1. Learning to Rank 是什么？**

Learning to Rank 是学习如何给候选对象排序的方法，常用于搜索、推荐和广告排序。它优化的不是单个样本分类是否正确，而是同一个 query、session 或用户下候选结果的相对顺序。

**2. pointwise 排序是什么？**

pointwise 把排序问题转成单样本分类或回归，比如预测每个商品的点击概率，再按概率排序。优点是简单，缺点是没有直接建模同组候选之间的相对顺序。

**3. pairwise 排序是什么？**

pairwise 关注一对样本之间谁应该排在前面，比如正样本分数应该高于负样本。OTTO 项目用的 rank:pairwise 就是这类思想，更贴近 session 内排序。

**4. listwise 排序是什么？**

listwise 直接从整个候选列表角度优化排序质量，比如优化 NDCG 或 ListNet 类目标。它更贴近最终排序指标，但训练和实现通常更复杂。

**5. pointwise、pairwise、listwise 有什么区别？**

pointwise 看单个样本，pairwise 看样本对，listwise 看整个列表。推荐排序更关注列表顺序，因此 pairwise 和 listwise 通常比普通 pointwise 更贴近业务目标。

**6. 为什么推荐排序不一定只看点击概率？**

因为推荐最终关注的是前 K 个结果的顺序，以及点击、转化、留存、GMV 等多目标。一个商品点击概率高但转化低，不一定是更好的推荐结果。

**7. 为什么排序模型要按 session 或 query 分组？**

排序关系通常只在同一个 query 或 session 内有意义。不同 session 的候选商品没有直接可比性，所以需要按 group 组织样本。

**8. group 信息在排序模型里有什么作用？**

group 告诉模型哪些候选属于同一个排序列表，pairwise 比较只应在同一个 group 内进行。如果不传 group，模型无法正确学习 session 内候选商品的相对排序。

**9. 为什么 OTTO 用 pairwise 比普通二分类更合理？**

OTTO 的目标是每个 session 推荐 Top20 商品，核心是候选商品之间的相对排序。pairwise 让正样本分数高于负样本，更接近 Recall@20 的排序目标。



## 6. 特征工程

**1. 特征工程为什么重要？**

特征工程把原始日志转化成模型能理解的信号，决定了模型能否捕捉用户意图和商品价值。对于 XGBoost 这类表格模型，特征质量往往直接决定上限。

**2. 常见用户侧特征有哪些？**

包括活跃天数、最近活跃时间、点击/购买次数、消费金额、偏好类目、留存状态、历史转化率等。LTV/LT 场景还会关注活跃衰减、消费频率和生命周期阶段。

**3. 常见商品侧特征有哪些？**

包括商品曝光量、点击量、加购量、下单量、点击率、转化率、价格、类目、品牌、热度趋势等。OTTO 项目里 item_event_cnt、item_order_per_cart 就属于商品侧特征。

**4. 常见交叉特征有哪些？**

交叉特征刻画用户和商品之间的个性化关系，比如用户是否点击过该商品、最近一次交互时间、交互次数、用户对该类目的偏好。OTTO 里的 session-aid 特征就是交叉特征。

**5. 时间特征为什么重要？**

用户兴趣有时效性，最近行为通常比很久之前的行为更能反映当前意图。电商 session 场景尤其强调短期兴趣，所以最近点击、最近加购、最后位置很重要。

**6. 转化率特征为什么有用？**

转化率特征能衡量商品从点击到加购、从加购到下单的能力。它不仅反映热度，还反映商品是否真正有商业价值。

**7. 历史统计特征如何避免数据泄漏？**

构造特征时只能使用预测时刻之前能看到的数据，不能使用未来标签窗口的信息。时间切分、滑动窗口统计和严格区分训练/验证时间边界是常用做法。

**8. 特征缺失为什么可以填 -1？**

对于树模型来说，特殊值可以作为缺失状态被学习到。填 -1 的前提是这个值不和正常取值混淆，比如计数、比例、时间差等特征通常非负。

**9. 如果商品是新商品，没有历史统计特征怎么办？**

可以用类目、品牌、价格、文本、图片等内容特征补充，也可以用同类商品统计或默认值。上线系统还需要探索流量让新商品逐步积累行为。

**10. 如何判断一个特征是否有效？**

可以看离线指标增益、交叉验证稳定性、特征重要性、消融实验和线上 A/B 实验。不能只看单次训练结果，因为可能受采样和数据波动影响。



## 7. 样本构造与负采样

**1. 什么是正样本？**

正样本是发生了目标行为的样本，比如用户点击、加购或购买的商品。在 OTTO 中，候选商品出现在对应类型 label 里，就可以作为该任务正样本。

**2. 什么是负样本？**

负样本是没有发生目标行为的样本。在隐式反馈推荐中，负样本通常是近似负样本，因为用户没点或没买不一定代表不喜欢，可能只是没看到或没来得及操作。

**3. 推荐系统里的负样本怎么构造？**

常见方式包括曝光未点击、候选未转化、随机采样未交互商品、热门负采样和困难负采样。不同构造方式会影响训练分布和模型偏差。

**4. 为什么不能把所有没买的商品都当负样本？**

商品库很大，用户没买绝大多数商品并不代表不喜欢，只是没有曝光或没有机会接触。全部当负样本会引入大量噪声，也会导致样本极度不平衡。

**5. 曝光未点击能不能作为负样本？**

通常可以作为较强负样本，因为用户看到了但没有点击。不过它仍不是绝对负样本，可能受位置、展示样式和用户当时状态影响。

**6. 随机负采样有什么问题？**

随机负样本可能太容易，模型学到的是区分热门和冷门，而不是细粒度偏好。它也可能和线上候选分布不一致，导致训练和预测有偏差。

**7. 困难负样本是什么？**

困难负样本是模型容易误判为正的负样本，比如和用户历史兴趣相似但最终没有转化的商品。适量困难负样本能提高排序模型区分能力。

**8. 正负样本不均衡怎么办？**

可以做负采样、类别权重、调整损失函数、分层采样或优化排序指标。推荐中负样本通常远多于正样本，采样是非常常见的做法。

**9. 负采样比例会影响模型吗？**

会。负样本太少，模型区分能力不足；负样本太多，训练成本高且容易被负样本主导。比例需要结合验证指标和训练效率调节。

**10. OTTO 项目中的负样本怎么理解？**

候选集中未出现在对应 label 中的商品被当作负样本，但它不一定是真正用户不喜欢，只能说明在验证窗口内没有发生该行为。因此它是隐式反馈下的近似负样本。



## 8. 评估指标

**1. AUC 是什么？**

AUC 是 ROC 曲线下面积，可以理解为随机抽一个正样本和负样本，模型把正样本排在负样本前面的概率。它衡量整体排序能力，不依赖固定阈值。

**2. 准确率在样本不均衡时有什么问题？**

如果负样本远多于正样本，模型全部预测为负也可能有很高准确率，但没有业务价值。所以不均衡场景更需要看 Recall、Precision、AUC、F1 或排序指标。

**3. Precision 和 Recall 有什么区别？**

Precision 关注预测为正的样本里有多少是真的，Recall 关注真实正样本中有多少被找回。推荐召回场景通常更重视 Recall@K。

**4. F1-score 是什么？**

F1 是 Precision 和 Recall 的调和平均，用于综合衡量查准率和查全率。当两者都重要时，可以使用 F1。

**5. Recall@K 是什么？**

Recall@K 衡量真实相关物品中有多少出现在模型推荐的前 K 个结果里。OTTO 使用 Recall@20，表示看前 20 个推荐是否覆盖真实点击、加购或下单商品。

**6. 推荐系统为什么常用 Recall@K？**

因为推荐页面展示位置有限，用户通常只会看到前 K 个结果。Recall@K 更贴近“前几个推荐有没有覆盖用户真正感兴趣的商品”。

**7. NDCG@K 是什么？**

NDCG@K 是考虑位置折损的排序指标，相关商品排得越靠前贡献越大。它比 Recall@K 更关注排序位置，但计算和解释稍复杂。

**8. MAP@K 是什么？**

MAP@K 是多个 query 或 session 的 Average Precision@K 的平均，既关注命中也关注命中位置。它常用于信息检索和推荐评估。

**9. Weighted Recall@20 怎么算？**

分别计算 clicks、carts、orders 三个任务的 Recall@20，再按业务权重加权求和。OTTO 中通常 orders 权重最高，因为购买最接近商业价值。

**10. 为什么 orders 权重最高？**

点击只是兴趣，加购是强意图，下单才是最终转化。电商推荐更关注真实购买和商业收益，所以 orders 的权重最高。

**11. 如果 clicks 提升但 orders 下降，怎么判断？**

要看最终加权指标和业务目标。如果业务更重视转化，orders 下降可能不可接受；还需要看 carts、GMV、用户体验和线上 A/B 结果。

**12. 离线指标和线上指标不一致怎么办？**

需要排查数据分布、样本构造、特征泄漏、线上延迟、召回覆盖、位置偏差和业务规则差异。最终还是要通过线上 A/B 实验验证。



## 9. 深度学习基础

**1. 神经网络的基本结构是什么？**

神经网络由输入层、隐藏层和输出层组成，每层通过线性变换和非线性激活提取特征。深层网络可以逐层学习更复杂的表示。

**2. 激活函数有什么作用？**

激活函数引入非线性，否则多层线性变换仍然等价于一层线性模型。常见激活函数包括 ReLU、Sigmoid、Tanh、GELU。

**3. ReLU 为什么常用？**

ReLU 计算简单，正区间梯度稳定，能缓解 Sigmoid/Tanh 的梯度消失问题。但它也可能出现神经元死亡问题。

**4. 梯度消失是什么？**

梯度在反向传播过程中越来越小，导致前层参数几乎无法更新。深层网络和 RNN 中都可能出现这个问题。

**5. Dropout 的作用是什么？**

Dropout 在训练时随机丢弃部分神经元，减少神经元之间的共适应，从而缓解过拟合。验证和测试时通常关闭 Dropout。

**6. BatchNorm 的作用是什么？**

BatchNorm 对中间层输入做归一化，使训练更稳定、收敛更快，并有一定正则化效果。它在训练和推理阶段使用的统计量不同。

**7. train 模式和 eval 模式有什么区别？**

train 模式会启用 Dropout，并使用当前 batch 统计量更新 BatchNorm；eval 模式会关闭 Dropout，并使用训练阶段累计的 BatchNorm 统计量。验证和测试必须用 eval。

**8. CNN 为什么适合图像？**

CNN 利用局部连接和参数共享，能有效捕捉图像中的局部模式，同时降低参数量。卷积层提取局部特征，深层网络组合成高级语义。

**9. 1×1 卷积有什么作用？**

1×1 卷积可以做通道维度的信息融合、升维或降维，减少计算量，也可以增加非线性表达能力。它在 Inception、ResNet 等结构中很常见。

**10. RNN 适合处理什么数据？**

RNN 适合序列数据，如文本、时间序列和用户行为序列。它通过隐藏状态传递历史信息，但长序列中容易出现梯度消失和并行效率低的问题。

**11. LSTM 如何缓解梯度消失？**

LSTM 通过输入门、遗忘门、输出门和细胞状态控制信息流，使重要信息能在较长时间内保留。相比普通 RNN，它更适合长序列建模。



## 10. Transformer / 大模型

**1. Transformer 的核心结构是什么？**

Transformer 的核心是 self-attention、多头注意力、前馈网络、残差连接和 LayerNorm。它不依赖 RNN 的递归结构，可以并行处理序列。

**2. Self-Attention 是什么？**

Self-Attention 是让序列中每个位置根据与其他位置的相关性聚合信息。它可以动态建模长距离依赖，因此适合文本和用户行为序列。

**3. Q、K、V 分别是什么？**

Q 是 Query，表示当前位置要查询什么；K 是 Key，表示其他位置提供什么索引；V 是 Value，表示真正被聚合的信息。Attention 通过 Q 和 K 计算权重，再对 V 加权求和。

**4. Attention 分数为什么除以根号 d？**

当维度较大时，Q 和 K 的点积方差会变大，softmax 后容易过于尖锐，导致梯度不稳定。除以根号 d 可以缩放分数，使训练更稳定。

**5. Multi-Head Attention 有什么作用？**

多头注意力让模型从多个子空间学习不同关系，比如局部关系、长期依赖、行为类型关系等。多个 head 的结果拼接后可以表达更丰富的信息。

**6. Position Encoding 为什么需要？**

Self-Attention 本身不包含序列顺序信息，所以需要位置编码告诉模型 token 或行为的先后顺序。用户行为序列建模中，时间顺序非常关键。

**7. Transformer 为什么可以并行训练？**

Transformer 不像 RNN 那样必须按时间步递归计算，训练时可以同时计算所有位置之间的 attention。因此在 GPU 上并行效率更高。

**8. BERT 和 GPT 有什么区别？**

BERT 是 Encoder-only，常用于理解任务，通过 Masked Language Modeling 预训练；GPT 是 Decoder-only，自回归预测下一个 token，更适合生成任务。

**9. Masked Attention 是什么？**

Masked Attention 会遮住当前位置之后的信息，防止模型在预测下一个 token 时看到未来。GPT 这类自回归模型必须使用 causal mask。

**10. LayerNorm 的作用是什么？**

LayerNorm 对每个样本的特征维度做归一化，使训练更稳定。Transformer 中通常和残差连接配合使用。

**11. 大模型预训练和微调有什么区别？**

预训练是在大规模通用数据上学习基础能力，微调是在特定任务或领域数据上适配目标任务。岗位中的 LTV/LT 可能更多涉及使用预训练模型能力做业务适配。

**12. LoRA 是什么？**

LoRA 是一种参数高效微调方法，通过在部分权重旁边加入低秩矩阵来学习任务增量，而不是更新全部参数。它能降低显存和训练成本。

**13. Transformer 怎么用于用户行为序列建模？**

可以把用户历史行为中的 item、行为类型、时间位置等看成序列 token，用 embedding 表示后输入 Transformer。模型通过 self-attention 学习不同行为之间的依赖，用于预测点击、转化、留存或 LTV。

**14. 用户行为里的 item 可以类比成 NLP 里的什么？**

可以类比成 token。用户的行为序列类似一句话，模型根据前面的 item 和行为预测后续兴趣或目标行为。

**15. 大模型在推荐系统里有什么落地难点？**

主要难点是推理成本高、延迟要求严格、用户行为数据和文本数据结构不同、线上更新频繁，以及需要和现有召回排序链路结合。通常不会直接用大模型替代全链路，而是用于表征、特征增强、重排或辅助理解。



## 11. 多目标学习 / 多任务学习

**1. 什么是多任务学习？**

多任务学习是在一个模型中同时学习多个相关任务，通常底层共享表示，上层为不同任务设计独立输出。它能利用任务之间的相关性，提高数据利用效率。

**2. 多任务学习有什么优势？**

相关任务可以共享底层特征，缓解单任务数据不足，提高泛化能力。比如 CTR、CVR、LTV、留存之间存在关联，可以通过多任务共同学习用户表示。

**3. 多任务学习有什么问题？**

如果任务之间目标不一致，可能产生负迁移或梯度冲突。比如优化点击可能和优化购买、留存不完全一致。

**4. 多个任务的 loss 怎么融合？**

常见做法是加权求和，例如 total loss = w1 * click_loss + w2 * cart_loss + w3 * order_loss。权重可以手工设定，也可以用不确定性加权、动态权重或梯度平衡方法学习。

**5. Shared-bottom 是什么？**

Shared-bottom 是多任务学习中最简单的结构：底层网络共享，上层每个任务有独立 tower。优点是简单高效，缺点是任务冲突时共享层可能互相干扰。

**6. MMOE 是什么？**

MMOE 是多门控混合专家模型，用多个 expert 表示不同特征模式，每个任务通过自己的 gate 选择 expert 组合。它比简单 shared-bottom 更能处理任务差异。

**7. PLE 是什么？**

PLE 进一步区分共享专家和任务专属专家，既学习任务共性，也保留任务差异。它常用于多目标推荐和广告预估。

**8. ESMM 是什么？**

ESMM 常用于 CTR 和 CVR 联合建模，通过曝光到点击、点击到转化的链路建模缓解样本选择偏差和数据稀疏问题。它利用 CTCVR = CTR × CVR 的关系。

**9. 为什么 CTR 和 CVR 经常联合建模？**

CTR 反馈多但更浅，CVR 反馈少但更接近业务价值。联合建模可以让 CVR 任务借助 CTR 学到更好的用户和商品表示。

**10. clicks、carts、orders 能不能做成多任务模型？**

可以。clicks、carts、orders 本身存在从兴趣到转化的漏斗关系，可以共享底层 session/item 表示，再用不同 task tower 分别预测三类行为。

**11. 如果把 OTTO 改成深度多任务模型，怎么设计？**

可以用 item embedding、行为类型 embedding、位置/时间 embedding 表示 session 序列，底层用 Transformer 或 attention 提取 session 表示，上层接 click、cart、order 三个 tower。最终按业务权重融合三个任务分数做排序。

**12. 多目标之间冲突怎么办？**

可以调整 loss 权重、使用 MMOE/PLE 等结构、做梯度裁剪或梯度冲突处理，也可以在重排阶段加入业务规则。关键是明确主目标，比如电商里 orders 或 GMV 可能比 clicks 更重要。



## 12. 推荐模型

**1. 协同过滤是什么？**

协同过滤根据用户和物品的历史交互发现相似用户或相似物品，再进行推荐。它不依赖内容特征，但对冷启动和稀疏数据比较敏感。

**2. UserCF 和 ItemCF 有什么区别？**

UserCF 找相似用户，推荐相似用户喜欢的物品；ItemCF 找相似物品，推荐用户历史交互物品的相似物品。电商中 ItemCF 更常用，因为商品相似关系相对稳定。

**3. Item-to-Item 共现和 ItemCF 有什么关系？**

Item-to-Item 共现可以看作一种简化的 ItemCF，通过同一 session 或同一用户历史中共同出现的商品计算相似关系。OTTO 项目的共现召回就是典型 item-based 思路。

**4. 矩阵分解是什么？**

矩阵分解把用户-物品交互矩阵分解成用户向量和物品向量，通过向量点积预测偏好。它能学习隐向量表示，但对序列行为和上下文建模有限。

**5. Word2Vec 为什么可以用于 item embedding？**

可以把用户行为序列看成句子，把 item 看成词，利用上下文共现学习 item 向量。这样相似使用场景或相似兴趣下出现的商品向量会更接近。

**6. 双塔模型是什么？**

双塔模型分别用 user tower 和 item tower 学习用户向量和物品向量，通过内积或相似度做匹配。它适合大规模召回，因为物品向量可以离线预计算，线上只需向量检索。

**7. 为什么双塔模型适合召回？**

召回阶段要求低延迟和大规模检索，双塔模型可以把用户和物品映射到同一向量空间，用 ANN 快速找 TopK。相比交叉网络，它牺牲部分精度换取效率。

**8. FM 是什么？**

FM 是因子分解机，通过隐向量建模二阶特征交互，适合高维稀疏类别特征。它在推荐和广告预估中很经典。

**9. DeepFM 是什么？**

DeepFM 结合 FM 和深度神经网络，FM 学低阶特征交互，DNN 学高阶非线性组合。它常用于 CTR 预估。

**10. DIN 是什么？**

DIN 是深度兴趣网络，通过 attention 根据候选商品动态关注用户历史行为中相关的部分。它适合电商精排，因为用户兴趣和候选商品强相关。

**11. DIEN 是什么？**

DIEN 在 DIN 基础上进一步建模用户兴趣的演化过程，通常使用序列结构捕捉兴趣变化。它更关注用户兴趣随时间如何发展。

**12. 如果优化 OTTO，会不会加入 Item2Vec 或 Transformer？**

会。Item2Vec 可以提升召回覆盖，Transformer 可以建模 session 行为序列中的短期兴趣和行为依赖。二者都能弥补纯共现和手工统计特征的不足。



## 13. PyTorch 工程基础

**1. Dataset 和 DataLoader 是什么？**

Dataset 定义如何读取单个样本，DataLoader 负责批量加载、shuffle、多进程读取和 batch 组织。它们是 PyTorch 训练数据管道的核心。

**2. batch_size 是什么？**

batch_size 是每次训练送入模型的样本数量。过小训练不稳定，过大占显存多且可能影响泛化，需要结合显存和任务调节。

**3. shuffle 有什么作用？**

shuffle 会打乱训练样本顺序，减少模型受数据排列影响，提升训练稳定性。验证和测试阶段通常不需要 shuffle。

**4. model.train() 和 model.eval() 有什么区别？**

train 模式启用 Dropout 并更新 BatchNorm 统计量；eval 模式关闭 Dropout，BatchNorm 使用固定统计量。验证和推理时必须切到 eval。

**5. torch.no_grad() 有什么作用？**

它会关闭梯度计算，减少显存和计算开销。验证和推理阶段不需要反向传播，所以应使用 no_grad。

**6. loss.backward() 做了什么？**

它根据计算图自动计算 loss 对模型参数的梯度，并把梯度存到参数的 grad 属性里。之后 optimizer.step() 会根据这些梯度更新参数。

**7. optimizer.zero_grad() 为什么需要？**

PyTorch 默认梯度是累加的，如果不清空，上一个 batch 的梯度会影响当前更新。所以每次反向传播前通常要 zero_grad。

**8. state_dict 是什么？**

state_dict 是模型参数和 buffer 的字典形式，常用于保存和加载模型。保存 state_dict 比保存整个模型对象更灵活。

**9. embedding 层是什么？**

embedding 层把离散 ID 映射成连续向量，比如 user_id、item_id、类别 ID。推荐系统中 embedding 是建模稀疏类别特征的核心。

**10. 如何处理变长序列？**

常见做法包括 padding、mask、截断、按长度排序、pack_padded_sequence 或 attention mask。Transformer 中通常用 mask 避免模型关注 padding 位置。




## 15. 业务开放题

**1. 你怎么理解用户生命周期价值？**

用户生命周期价值是用户在未来一段时间内对平台贡献的总价值，不只包括一次点击或一次购买，还包括复购、留存、活跃和长期收益。建模时要关注短期行为和长期价值之间的平衡。

**2. 如何判断一个用户是否高价值？**

可以看历史消费金额、购买频率、活跃频率、留存周期、复购率、品类偏好和未来预测价值。高价值用户不一定只是当前消费高，也可能是未来增长潜力高。

**3. 如果模型预测用户会流失，业务上怎么干预？**

可以做个性化召回、优惠券、push、内容推荐、会员权益提醒等。但干预要看用户流失原因，不能对所有用户采用同一种策略。

**4. 如果模型点击率高但留存低，怎么分析？**

需要检查模型是否推荐了短期吸引点击但低质量或不匹配长期兴趣的内容。可以进一步分析停留时长、负反馈、复访率、转化率和用户分层表现。

**5. 新模型离线指标提升但线上下降，怎么排查？**

优先排查训练验证集是否和线上分布一致，是否存在特征泄漏，线上特征是否延迟或缺失，召回排序链路是否一致，以及离线指标是否真的对齐业务目标。

**6. 数据分布发生变化怎么发现？**

可以监控特征分布、预测分数分布、关键业务指标、PSI、KL 散度和不同用户分层指标。发现漂移后需要判断是短期活动影响还是长期分布变化。

**7. 业务目标从点击变成下单，模型怎么改？**

需要调整标签、样本权重、评价指标和多目标融合权重，更重视加购、购买、GMV 等目标。排序时不能只按点击概率，而要综合转化概率和价值。

**8. 如果老板要求解释模型为什么这么推荐，怎么做？**

可以从特征贡献、相似商品、用户历史行为、召回来源和规则层解释。树模型可用特征重要性或 SHAP，深度模型可结合 attention、相似行为和可解释特征输出。



## 16. 最高优先级背诵题

**1. 为什么不用普通分类，而用排序？**

因为推荐任务最终不是判断某个商品是不是正样本，而是在同一个 session 下把更可能发生点击、加购、下单的候选商品排到前 20。所以排序关系比单点分类概率更贴近 Recall@20 的目标。

**2. 为什么关注多目标？**

电商行为天然是从点击到加购再到下单的转化链路，clicks 代表兴趣，carts 代表强意图，orders 更接近商业价值。岗位里的 LTV/LT 也是多目标和长期价值建模，所以这个项目可以体现我对多行为目标融合的理解。

**3. 为什么 XGBoost 适合这个项目？**

这个项目主要使用结构化统计特征，包括商品侧、session 侧、session-aid 交互侧特征。XGBoost 对结构化特征、非线性关系和特征组合建模能力较强，训练稳定，适合做候选排序任务。

**4. 如果后续优化这个项目，你会怎么做？**

可以从三方面优化：召回侧引入 Item2Vec、双塔或序列召回提升候选覆盖；排序侧尝试多任务深度模型，让 clicks、carts、orders 共享表示；序列建模侧用 Transformer 捕捉 session 的短期兴趣和长期偏好。

**5. 如果问你这个项目最大的困难是什么？**

最大的困难是数据规模大、候选样本多，同时要避免验证和训练过程的数据泄漏。我通过分块处理、内存压缩、按 session 构造验证和 GroupKFold 来保证训练可运行且评估尽量可靠。

**6. 如果问你为什么 orders 指标更重要？**

orders 是最终购买行为，最接近电商业务价值；clicks 只是兴趣，carts 是强意图，但都不一定转化为真实收益。因此 Weighted Recall@20 中 orders 权重最高。

**7. 如果问你如何和岗位 LTV/LT 联系？**

OTTO 项目建模的是用户 session 内从点击到加购再到下单的行为链路，岗位的 LTV/LT 建模关注用户长期价值和留存周期。二者都需要从用户行为序列中理解意图、转化和长期价值。
